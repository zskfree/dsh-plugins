# DSH 本地插件库

这里统一存放本机自行开发、维护的 DSH 插件源码，以一个 Git 仓库管理。固定位置：`D:/DEV/projects/dsh-plugins`。

这里不是 DSH 安装目录，也不是运行时缓存目录；不修改 DSH 自带插件或 `app.asar`。第三方插件仍优先通过 DSH 插件管理器管理，不默认复制到这里。

## 目录约定

- 每个本地插件占用一个独立子目录，目录名优先与其 npm 包名一致。
- 插件自己的 README 记录用途、兼容版本、安装入口、验证方法及限制。
- 源码、插件清单、必要的客户端产物及依赖锁文件纳入 Git；依赖目录、虚拟环境、运行状态与秘密不纳入 Git。
- 默认不在插件子目录再初始化嵌套仓库，也不把这里配置成 pnpm workspace；各插件继续使用自己的工具链。

## 当前插件

| 目录 | 用途 | 状态 |
| --- | --- | --- |
| [dsh-lambda-dashboard](./dsh-lambda-dashboard/README.md) | 在 DSH 桌面独立面板显示已有的 Lambda 额度看板，不重写业务页面 | 当前本机已链接安装并启用 |

## 开发与安装

1. 在此目录下创建插件子目录，按当前 DSH 插件接口编写清单、入口和说明。
2. 使用插件自己的局部依赖及测试命令；不要修改系统全局依赖或代理配置。
3. 通过 DSH 插件管理器安装本地链接，例如 `link:D:/DEV/projects/dsh-plugins/dsh-lambda-dashboard`，再确认插件已启用且运行正常。
4. 客户端修改后按实际运行方式重新加载桌面窗口，必要时重启 DSH；不要默认承诺热更新生效。
5. 移动插件前检查安装链接。先调整管理器中的链接，再验证新路径；不要仅移动目录后留下旧引用。

新增、移除或迁移插件后，同步维护本页和插件自己的说明。

## Git 与安全

```bash
git -C D:/DEV/projects/dsh-plugins status --short
git -C D:/DEV/projects/dsh-plugins diff --check
```

根目录 `.gitignore` 排除常见依赖、缓存、状态、`.env` 和私钥文件；但忽略规则不能替代秘密审查。提交前检查实际暂存文件，禁止提交密码、Cookie、令牌、真实账户数据或私钥。必要的示例配置只使用占位符。

初始化仓库不等于备份：首次提交、设置远程仓库、推送及发布都需用户明确授权。不自动更改全局 Git 配置。
